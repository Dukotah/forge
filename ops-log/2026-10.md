### Why this guide / why now

LeakCheck had 7 guides covering: accidentally committed API key, scanning git history for secrets, preventing secrets with pre-commit hooks, finding hardcoded API keys in a codebase, removing a secret from git history, API key storage best practices, and vibe coding security checklist. None covered what to do with the API key itself after a leak — rotation.

The gap is real: the “accidentally committed” guide focuses on git cleanup; the “API key storage” guide focuses on storage patterns going forward. Neither covers the incident response step: how to revoke the compromised key at the provider and issue a replacement. The query cluster (“rotate api key”, “how to rotate api key”, “rotate leaked api key”, “api key rotation checklist”) is high-intent (someone in an active incident or preparing for one) and not covered by any existing LeakCheck guide.

### Guide content summary

**JSON-LD:** TechArticle with nested FAQPage (7 Q&As), datePublished/dateModified 2026-10-07

**Sections:**

1. **Rotate first, clean history second** — the core message: automated scanners may capture the key within minutes of a public push; rewriting history does not invalidate a credential that has been copied. Callout: open your provider dashboard NOW and revoke the key before reading further.

2. **5-step rotation checklist** — numbered steps: (1) revoke old key immediately, (2) generate replacement with minimum permissions, (3) find every consumer (env files, CI secrets, platform env vars, team vault), (4) deploy new key everywhere + verify each consumer, (5) confirm old key is dead with a test API call returning 401.

3. **Provider-specific rotation steps** — 6-card grid covering:
   - **OpenAI** — platform.openai.com → API keys; trash icon; Usage page audit check
   - **Stripe** — Dashboard → Developers → API keys; “Roll key” for zero-downtime vs. immediate Delete; restricted keys; Logs check
   - **AWS IAM** — IAM → Users → Security credentials; “Make inactive” first (preserves key ID for CloudTrail audit) then Delete; CloudTrail filter by access key ID
   - **Google Cloud** — separate paths for API keys (APIs & Services → Credentials) vs. service account keys (IAM & Admin → Service Accounts); Cloud Audit Logs check
   - **GitHub personal access tokens** — classic vs. fine-grained; Settings → Developer settings; 90-day expiry recommendation; Security log check
   - **Twilio** — Auth Token rolling (secondary token model for zero-downtime); API Key + Secret pairs for production

4. **Audit log table** — 6-provider table (AWS CloudTrail, GCP Cloud Audit Logs, Stripe Logs, OpenAI Usage, GitHub Security log, Twilio Monitor) with where-to-look and what-to-check columns.

5. **Prevent recurrence** — expiry settings: GitHub fine-grained 90 days, AWS STS/OIDC for CI, GCP Workload Identity Federation, Stripe restricted keys with minimum permissions, 90-day calendar reminders for keys without expiry support.

6. **Clean git history after rotation** — explains why rotation comes first; CTA to remove-secret-from-git-history guide; secondary CTA to LeakCheck scanner.

7. **FAQ** — 7 questions: still need git cleanup after rotation, how to detect key abuse, revoke vs. rotate, keeping old key live during migration, finding all consumers, LeakCheck live key detection, rotation frequency.

### Why this guide / why now

DepCheck had 6 guides covering: fix npm audit vulnerabilities, audit npm packages, typosquatting detection, license compliance, Docker vulnerability auditing, and tool comparison (npm audit vs Snyk vs Dependabot). None covered SBOM generation. The SBOM query cluster (“npm sbom”, “software bill of materials npm”, “generate sbom node.js”, “cyclonedx npm”, “npm sbom compliance”, “sbom for javascript project”) is growing with real regulatory tailwinds:

- **US Executive Order 14028** (2021): requires SBOMs for software sold to US federal agencies
- **EU Cyber Resilience Act** (CRA, 2024): requires SBOMs for commercial products with digital elements, enforcement phasing in 2027
- **Enterprise procurement**: SBOMs increasingly appear in vendor security questionnaires

The guide extends the DepCheck content cluster into supply chain security — a natural adjacent topic to typosquatting (existing guide) and CVE scanning (existing guides), and one that positions DepCheck as relevant to compliance-conscious enterprise developers.
