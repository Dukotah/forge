**New page:** `depcheck/guides/fix-npm-audit-vulnerabilities.html`
Live URL: https://labs.copperbaytech.com/depcheck/guides/fix-npm-audit-vulnerabilities.html

A ~900-word step-by-step remediation guide targeting the fix-intent query **"how to fix npm audit vulnerabilities"** — a developer who has just run `npm audit` and is staring at a report of critical, high, and moderate findings across direct and transitive packages.

**Article structure (all content is genuine, actionable, and accurate):**
- Reading the output — severity table (critical/high/moderate/low), direct vs. transitive distinction, how to get JSON output
- Step 1: `npm audit fix` (the safe semver-compatible path) — commit the lockfile after
- Step 2: Manual targeted upgrades for findings that require a major-version jump — changelog review
- Step 3: Transitive dependency overrides — Option A: upgrade the parent package; Option B: the `overrides` field in package.json (npm 8.3+), with equivalents for Yarn (`resolutions`) and pnpm (`pnpm.overrides`) — plus a callout warning that overrides can break the parent
- Step 4: No fix available yet — check GitHub issues for timeline, assess reachability of the vulnerable code path, check for patched forks, document accepted risk
- Step 5: Replace abandoned packages — when the fix will never come; examples of commonly replaced deprecated packages; DepCheck CTA for finding unmaintained deps beyond CVEs
- Prevention in CI — `--audit-level` flag, committing lockfile, scheduled `npm outdated` reviews, DepCheck for non-CVE risk
- FAQ + FAQ JSON-LD schema (6 questions: why fix doesn't fix everything, --force safety, what transitive means, low/moderate severity calculus, no-fix strategy, audit-level in CI)
- Suite cross-links: LeakCheck, ExposureCheck, HardenCheck
