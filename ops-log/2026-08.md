**Eyebrow:** "History rewrite guide" — the fifth distinct guide category in LeakCheck:

**Article structure (TechArticle + FAQPage JSON-LD):**

1. **Why git rm isn't enough** — the mental model problem. Every commit is a permanent content-addressed snapshot; `git rm` adds a new commit that removes the file from the working tree but leaves all prior commits intact. Anyone with read access can check out an old SHA and read the original value.

2. **Before you start** — four-item checklist: rotate first, identify file-removal vs inline string-replacement, inventory all remote branches, notify collaborators before pushing (they must re-clone).

3. **Choose your tool** — two-card comparison: git-filter-repo (recommended: Git-project-endorsed, rewrites all refs including stash, handles inline string replacement) vs BFG Repo-Cleaner (alternative: faster on large binary repos, but does not rewrite stash refs by default, and has the HEAD-protection gotcha). Explicit note: avoid deprecated `git filter-branch`.

4. **git-filter-repo full workflow:**
   - Install (pip, Homebrew)
   - Fresh clone requirement and why (local reflog references old commits — don't run on existing working directory)
   - Option A: remove entire file (`--path .env --invert-paths --force`)
   - Option B: replace inline string value (`--replace-text /tmp/replacements.txt --force`)
   - Why filter-repo removes the origin remote after rewriting (intentional safety measure) and how to add it back
   - Force-push all branches and tags (`--force --all` + `--force --tags`)

5. **BFG Repo-Cleaner workflow:**
   - Bare clone requirement
   - Delete a file from all history
   - Replace a string (replacements.txt format)
   - Prune old unreachable objects before pushing
   - BFG's HEAD protection gotcha — the most commonly missed BFG limitation: BFG never modifies the most recent commit on protected branches, so if the secret is still in HEAD, it stays. Fix: make a clean HEAD commit first, then BFG rewrites historical commits only.
   - Stash gotcha: BFG doesn't process refs/stash; manual stash drop required after BFG

6. **After the force-push:**
   - Collaborator re-clone requirement (force-push changes every SHA downstream; git pull fails; save unpushed work as patches with `git format-patch` before re-cloning)
   - GitHub's object cache (old commits become unreachable but remain in GitHub's internal store until GC; up to 90 days for public repos; direct SHA URLs may still resolve; for private repos, open a GitHub Support ticket for immediate GC)
   - Fork problem — forks are independent repositories; you cannot update their history; notify fork owners to re-clone; for forks you own, run the rewrite workflow on each independently

7. **Verify the rewrite worked** — three-step verification: clone fresh from the remote (not local), search all commit diffs (`git log --all -p | grep -n "SECRET"`), search the working tree (`grep -r`), check stash list.

8. **Five common mistakes** as a visual callout list:
   - Running filter-repo on existing working directory (stale reflog)
   - Forgetting to push tags
   - Forgetting feature branches (fetch --all before rewriting)
   - BFG leaving HEAD unchanged when secret is still in latest commit
   - Treating the force-push as an immediate fix (GitHub's object cache)

9. **FAQ (7 questions):** GitHub cache timing; fresh clone requirement; fork handling; verification workflow; filter-repo and stash; BFG HEAD protection; collaborator re-clone procedure.
