### Guide content summary

**JSON-LD:** TechArticle with nested FAQPage (7 questions) as mainEntity

**Scope table** — what each accessible .git object reveals: `/.git/config` (Critical — remote URL, embedded tokens), `/.git/packed-refs` (High — all branch/tag SHAs), `/.git/objects/` (Critical — full repo reconstruction), `/.git/logs/HEAD` (Medium — author emails, timestamps), `/.git/HEAD` (Low — active branch name), `/.git/COMMIT_EDITMSG` (Low — recent commit message)

**7-step remediation sequence:**
1. Block access immediately — Nginx, Apache, Vercel, Netlify, Caddy, Cloudflare configs
2. Confirm scope — which .git paths were reachable (HEAD, packed-refs, objects/)
3. Check access logs — scan for git-dumper user agent signatures, object fetch patterns
4. Audit git history for secrets — gitleaks, git log -S, truffleHog
5. Rotate all credentials found in any commit, including deleted files
6. Assess source code confidentiality — if repo is private and source has competitive value
7. Breach notification assessment — GDPR Article 33 (72h DPA threshold), CCPA, client contracts

**Platform deny configs:** Nginx location block, Apache FilesMatch, Vercel vercel.json, Netlify _redirects, Caddy respond, Cloudflare WAF rule

None of them answers the upstream question: "where do I actually put the key instead?" ### Guide content summary

**JSON-LD:** TechArticle with nested FAQPage (7 questions) as mainEntity

**Sections:**

1. **Why keys end up in source code** — the root cause: quick-start documentation normalizes inline keys; developers copy the example and commit without thinking

2. **The .env file pattern** — dotenv setup for Node.js and Python, the three-file model (.env, .env.example, .gitignore), and the most common mistake (committing .env after adding to .gitignore without first running `git rm --cached`)

3. **Build-time vs. runtime environment variables** — the distinction that causes the most frontend security mistakes: NEXT_PUBLIC_/VITE_ prefixed variables are inlined into the client bundle and shipped to every browser. Includes a decision table (Stripe publishable key → client-side OK; OpenAI API key → server-side only; database password → server-side only, etc.) and the server-side proxy pattern for frontends that need to call secret-requiring APIs

4. **Platform-native secrets** — Vercel, Netlify, Railway, Render, GitHub Actions, Fly.io — how each platform injects secrets at runtime without touching any file on disk. Includes a tip on per-environment key separation

5. **When to use a secrets manager** — decision table comparing platform env vars vs. AWS Secrets Manager / HashiCorp Vault / Doppler, with the triggering requirements (multi-service access, automatic rotation, audit logs, SOC 2/HIPAA compliance)

6. **Mistakes to avoid** — 7 concrete mistakes with explanations: hardcoding in source, committing .env, using NEXT_PUBLIC_ for server secrets, logging process.env, bundling .env into Docker images, sharing secrets over Slack/email, using one key across all environments

7. **FAQPage** — 7 questions including the Docker push edge case (do I need to rotate a local-only .env?), encrypted secrets in public repos (no), and the correct first step when a key is found (rotate before rewriting history)
